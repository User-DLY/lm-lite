# lm-lite

给 **llama.cpp / llama-server** 套一个能看、能管的 Web 界面。

如果你在自己电脑上跑 GGUF 模型，又被 LM Studio 的体积劝退、被裸 `llama-server` 的交互劝退，
这个项目可能就是你要的：**一个 HTML 文件 + 三个 Python 文件，零依赖，双击就能用。**

> 作者是初三学生，这是课余折腾出来的东西。代码算不上优雅，但每一条注释都写着「为什么这么写」——
> 包括那些踩过的坑。希望它对后来的人有点用。

## 特性

**对话**
- 流式输出、Markdown 实时渲染、代码块高亮
- 思考过程（reasoning）独立折叠面板
- 随时停止、重新生成、复制
- 上下文环形进度，点击切换「百分比 ⇄ 已用/总数」

**性能监控**
- 当前并发 / 队列 / 完成数 / 异常 / 成功率 / 平均首字 / 平均速度 / 最慢一次
- TTFT、tok/s、prefill 速度、缓存命中率四条曲线
- 每次请求的完整详情（模型、时间、token、首字、速度、命中）

**推理队列**
- 左侧任务列表（可排序、可按来源筛选）
- 右侧选中详情
- 底部耗时柱状图，**可左右拖动**，点柱子能跳回对应任务

**模型管理**
- 加载 / 卸载，上下文长度、KV 精度、并发数可配
- 显存实时显示（含模型占用 / KV 占用 / 其他）
- 自动恢复上次的模型

**其他**
- 局域网访问 + IP 黑名单（拉黑即断连）
- 运行日志增量拉取
- 启动等待遮罩、单实例保护、网关崩溃自动重启

## 多用户与权限

本机访问（`127.0.0.1`）**永远是超级管理员**，无需登录 —— 密码与角色系统只用于拦局域网设备。

局域网访问时通过 `/login` 登录，分两种角色：

| 能力 | admin（管理员） | user（普通用户） |
|---|---|---|
| 对话、查看状态/显存 | ✓ | ✓ |
| 加载 / 卸载模型 | ✓ | ✗ 403 |
| 修改加载参数 | ✓ | ✗ 403 |
| 浏览本地磁盘选 GGUF | ✓ | ✗ 403 |
| 管理用户与密码 | ✓ | ✗ 403 |
| 拉黑设备、清空队列 | ✓ | ✗ 403 |
| 自己的聊天记录 | ✓ | ✓（按用户名隔离） |

**安全措施：**

- 密码用 **PBKDF2-HMAC-SHA256**（12 万次迭代）+ 随机盐存储，不保存明文
- 会话令牌 48 位十六进制随机（192 bit），HttpOnly Cookie
- 登录失败 10 次锁定 120 秒，防字典爆破；统一错误信息防用户名枚举
- 写操作校验 Origin（同源判据：Origin 主机必须等于请求来源 IP）
- admin 敏感操作写入 `audit.log`，局域网设备的操作额外弹 Windows 通知

**配置文件：** `auth.json`（首次通过设置页创建用户时自动生成）

> ⚠️ `auth.json` 含密码哈希、`audit.log` 含操作记录，都已在 `.gitignore` 中排除，**不要提交**。

## 界面预览

顶栏常驻状态：构建版本、当前身份、后端点状态、模型名、上下文、显存占用。

侧栏七个入口：对话 / 模型管理 / 性能监控 / 运行日志 / 推理队列 / 网络 / 设置。

其中「网络」页展示：局域网开关状态、本机访问地址（可一键复制）、用户数 / 设备数 / 请求数统计、在线设备列表（含客户端 UA 与访问次数）、用户列表与退出登录。

## 快速开始（Windows）

### 1. 准备 llama-server

去 [llama.cpp Releases](https://github.com/ggerganov/llama.cpp/releases) 下载适合你显卡的版本
（NVIDIA 选 CUDA、AMD 选 Vulkan 或 ROCm、纯 CPU 选 CPU），解压到任意目录。

### 2. 准备模型

下载任意 `.gguf` 文件，放在任意目录。

### 3. 配置

复制 `config.example.json` 为 `config.json`，改成你的路径：

```json
{
  "backend_dir": "D:\\llama.cpp\\build\\bin",
  "model_dir": "D:\\models"
}
```

或者用环境变量：

```bat
set LM_LITE_BACKEND=D:\llama.cpp\build\bin
```

### 4. 启动

```bat
python launcher.py
```

浏览器会自动打开 `http://127.0.0.1:9000`。

**没有 Python？** 装一个就行：[python.org](https://www.python.org/downloads/)（3.8+，无需任何第三方包）。

## 配置项

| 环境变量 | 说明 | 默认 |
|---|---|---|
| `LM_LITE_BACKEND` | llama-server 所在目录 | 见 `config.json` |
| `LM_LITE_LAN` | 设为 `1` 监听 `0.0.0.0`（局域网可访问） | 关闭 |
| `LM_LITE_GPU_TOTAL_MB` | 显存总量（非 8GB 卡时用来算百分比） | 8192 |

也可以用同目录的 `config.json`：

```json
{
  "backend_dir": "...",
  "model_dir": "..."
}
```

## 架构

```
浏览器 (index.html)
    ↓ HTTP/SSE
gateway.py  :9000      ← 转发 / 统计 / 队列 / 黑名单 / 进程管理
    ↓ OpenAI 兼容 API
llama-server :8081     ← llama.cpp
```

**为什么要有网关？** 因为 `llama-server` 只提供 API，不提供：进程管理、显存统计、请求队列、
多客户端来源区分。这些东西塞不进一个静态 HTML，所以有了 `gateway.py`。

三个文件的分工：

| 文件 | 职责 |
|---|---|
| `index.html` | 全部前端（HTML + CSS + JS，无构建步骤） |
| `gateway.py` | HTTP 服务、反向代理、统计、队列、模型进程管理 |
| `launcher.py` | 环境自检、启动网关、崩溃看护、单实例保护 |

## 已知限制

- **仅 Windows** —— 用了 PowerShell 采显存、`taskkill`、注册表读路径。
- **显存统计依赖 Windows 性能计数器**，某些驱动下可能读不到（前端会显示 `—`）。
- **单文件前端 4000+ 行** —— 拆开需要构建步骤，违背「零依赖」的初衷，所以没拆。
- **没有自动化测试**（除了 `api_cfg_test.py`）。
- **并发 > 1 时未充分验证** —— `-np 2` 会让 KV 缓存减半，默认保持 1。

## 设计参考来源（UI / 后端思路）

这个项目的很多交互不是凭空想的，参考了下面这些产品的做法。写在这里是为了让后来的人知道「为什么是这么设计的」，也方便继续对标。

### UI / 交互

| 参考对象 | 借鉴了什么 |
|---|---|
| **DeepSeek 官方**（chat.deepseek.com） | ① 会话右键菜单结构：重命名 / 置顶 / 分享 / **多选** / 删除<br>② 多选模式：顶部「已选择 N 个对话」+ 退出，每项前圆形复选框，底部批量「置顶 / 删除」<br>③ 会话项右侧「⋯」按钮唤起菜单（不依赖右键）<br>④ 消息操作条（复制 / 重新生成）放在气泡下方 |
| **LM Studio** | ① 模型加载参数的分组方式（上下文 / KV 精度 / 显存占用提示）<br>② 显存占用展示逻辑（模型占用 + KV 占用 + 其他）<br>③ 「加载 / 卸载」状态体现在按钮上 |
| **llama.cpp 官方 WebUI** | ① 流式输出时「思考内容」与「正文」分离展示<br>② 首字延迟（TTFT）与生成速度（tok/s）分开统计 |
| **ChatGPT / Claude 网页版** | ① 输入框自动增高（最多 180px 后内部滚动）<br>② 「回到底部」悬浮按钮<br>③ 上下文占用的环形指示 |

### 后端 / 协议

| 参考对象 | 借鉴了什么 |
|---|---|
| **OpenAI Chat Completions API** | 网关对外暴露的是同构接口（`/v1/chat/completions`），所以 DSH、Open WebUI、各类 SDK 都能直接接上 |
| **llama.cpp server** | `-np`（并行槽位）/ `-fa`（Flash Attention）/ `-b` `-ub`（批大小）等参数的语义与默认值 |
| **多客户端并发场景** | 多客户端来源区分（`X-LML-Web` 头 vs 外部 API），以及「本机请求优先」的调度策略 |

### 明确没做的
- **分享**：DeepSeek 有，这里没有 —— 本地模型场景下分享会话意义不大，且涉及隐私。
- **云端同步**：所有数据只在 `localStorage` 和 `last.json`，没有服务器。
